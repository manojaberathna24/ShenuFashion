1. Objective & Progress Summary
Objective: This report presents the developmental progress of the E-Commerce platform for Shenu Fashion Store. Currently, over 65% of the platform (consisting of the storefront UI, local and Firebase shopping cart synchronization, order placement validation, and administrative controls) is operational. This demonstrates substantial compliance with the CA 02 assessment guidelines.
2. Frontend Client Implementation
Home Page Hero Section Implementation
Figure 01: Home Page Hero Layout
The landing screen displays a responsive navigation bar and visual storefront banners. The container is constructed with clean grid frameworks that scale dynamically for desktop and mobile viewports.
Apparel Categories and Grid Layout
Figure 02: Store Categories and Promotions
Custom apparel categories (Women, Men, Accessories) are structured using flexbox containers. The layout features subtle hover interactions that improve user navigation to target item listings.
Dynamic Product Listing Catalog
Figure 03: Product Listing Grid
The store inventory list fetches active product records dynamically from the NoSQL database. The item cards render current prices, stock metrics, and ratings based on user feedback.
Catalog Search and Filter System
Figure 04: Product Filters and Sorting
An advanced filtering panel allows users to query products by sizing parameters, color swatches, and price brackets. The Javascript controller adjusts the layout immediately without page reloads.
Product Detail Visual Display
Figure 05: Product Detail Layout
A dedicated page generated dynamically using target product document keys. It shows high-resolution images, descriptive text, pricing hierarchies, and sizes configurations.
Interactive Sizing and Color Selection
Figure 06: Variant Selection Panel
Interactive inputs map size and color selection states prior to order generation. The UI validates stock levels and registers the selected variant attributes inside the browser cart.
Empty Shopping Cart Interface
Figure 07: Empty Shopping Cart State
A fallback interface rendered when no active products are registered in the customer session. It provides direct call-to-actions guiding users to catalog pages.
Shopping Cart Items List
Figure 08: Shopping Cart Items List
Displays items currently queued for purchase. The layout renders metadata fields including chosen size and color, linking directly with the database definitions.
Cart Quantity and Selection Modifiers
Figure 09: Shopping Cart Quantity Modifiers
Operational handlers allowing customers to update quantity levels or remove item rows. The JavaScript listener recalculates overall totals immediately upon value updates.
Order Checkout Billing Summary
Figure 10: Billing and Delivery Summary
Displays subtotal calculations, shipping rates based on cart thresholds (free shipping above LKR 5,000), and presents final billing values.
Shipping Details Form Validation
Figure 11: Shipping Details Entry Page
The first step of the checkout process requires users to fill out contact details and delivery addresses. The fields contain validators to verify data integrity.
Secure Payment Selection Form
Figure 12: Checkout Payment Selection
A toggle interface presenting credit card form inputs, PayPal gateways, and Cash on Delivery choices to the user. It structures payment parameters prior to transaction submittals.
Order Confirmation and ID Generation
Figure 13: Order Success Confirmation
The confirmation screen triggered upon successful database commits. It renders a unique tracking Order ID generated by Firestore to trace the shipment path.
User Account Registration Page
Figure 14: User Account Registration Page
Sign-up form designed for new customers. It collects credentials, implements format checks, and routes profiles to the authentication controller.
User Portal Authentication
Figure 15: User Login Portal
The login screen handling validation states. It checks credential matching and manages session routing based on user verification tokens.
3. Backend Administration Panel
Admin Operations Dashboard
Figure 16: Admin Analytics Dashboard
The central analytics panel displaying platform metrics (total transactions, inventory figures, active customers) compiled dynamically from database queries.
Inventory CRUD Operations Table
Figure 17: Admin Inventory Management Grid
A dashboard table containing product listings. It enables CRUD configurations and allows admins to track item stock levels, categories, and remove obsolete items.
Product Attribute Modification Modal
Figure 18: Admin Add/Edit Product Modal
An editing modal overlay built to update product attributes. Changes made to product names, prices, tags, and sizes are updated immediately in Firestore.
Customer Order Status Configuration
Figure 19: Admin Order Control Panel
A management view showing customer transactions. Administrators can inspect details and update delivery states (Pending, Processing, Shipped, Delivered) using Firestore methods.
4. Database & Integrations (Firebase Console)
Cloud Firestore Collections Schema
Figure 20: Firebase Cloud Firestore Database Schema
Live Firebase console showing the NoSQL backend environment. Document hierarchies partition active collections for products and orders, serving as the system's datastore.
Firebase User Authentication Console
Figure 21: Firebase Authentication User Records Management
Displays the active user authentication records managed via the Google Firebase backend. It securely stores passwords, handles login sessions, and governs user tokens.
Firestore Real-time Transactions Database
Figure 22: Firestore Real-time Orders Collection
Showcases the saved customer transactions stored in Firestore collections. The collection tracks checkout attributes including addresses, shipping categories, status flags, and item details.
